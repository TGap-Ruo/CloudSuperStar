# 授权码、后台管理与费用统计

这份文档说明「谁能用、用多少、花了多少钱」三件事。

---

## 一、整体模型（先看这个）

```
                     ┌──────────────────────────────┐
   打开控制台（免登录）│  填学习通账号密码             │
                     │  填授权码（选填）             │
                     └──────────────┬───────────────┘
                                    │ 点「开始刷课」
                                    ▼
                       校验：有授权码？→ 用授权码次数
                             没有？→ 用登录账号的额度
                             都没有？→ 拒绝，并提示
                                    │
                                    ▼
                           弹窗确认消耗来源与剩余次数
                                    │
                                    ▼
                        启动任务（扣 1 次）→ 跑完
                                    │
                          任务失败？→ 自动退还 1 次
```

三条关键规则：

1. **进页面不需要登录**，页面上有个「授权码（选填）」输入框；
2. **开始刷课**必须满足其一：有有效授权码，或已登录且账号还有额度；两者都有时**优先扣授权码**；
3. **一次刷课 = 扣 1 次**（一次里刷几门课、几个章节都算 1 次）；**失败自动退还**。

授权码与用户是**两种独立身份**：授权码不能充值到用户账号上，用户额度也不能转成授权码。
日常运营用授权码就够了，用户（账号）是可选的补充。

## 二、授权码

后台「授权码管理」→ 生成，只要填两个核心字段：

| 字段 | 说明 |
| --- | --- |
| **数量** | 一次生成几张 |
| **每张次数** | 这张授权码能跑几次；填 `-1` 表示不限次数 |
| 名称/备注 | 方便自己认人（例如 "XX学院-张三"） |
| 到期时间 | `2026-12-31` 或 `2026-12-31 23:59:59`，留空表示长期有效 |

列表里能直接看到 **已用/总次数、剩余次数、这张授权码累计花掉的 token 与费用**，并支持：

* **复制**：把授权码发给用户；
* **改次数**：随时调整总次数（例如续期）；
* **禁用/启用**：临时停用某张授权码；
* **重置已用**：把已用次数清零；
* **删除**：彻底删除（已产生的用量记录会保留）。

授权码是随机生成的 10 位大写字母+数字，已剔除 `0/O`、`1/I/L` 等易混字符，方便人工抄写。

## 三、用户（可选）

如果不想用授权码，也可以给用户开账号：管理员在「用户管理」里创建，填用户名、密码、角色（管理员/普通用户）、
剩余额度、每日任务上限、并发上限。用户登录后不填授权码时，就消耗自己账号的额度。

* 密码使用 PBKDF2-SHA256 加盐哈希存储，不存明文；
* 登录失败限流：同一 IP 5 分钟内失败 8 次后拒绝；
* 会话用签名 Cookie，默认有效期 `server.session_timeout_minutes`（12 小时），密钥落盘在 `data/.session_secret`；
* 可以给用户生成 API Key，用于脚本调用（请求头 `X-Api-Key`），此时任务归属该用户。

首次部署会自动创建初始管理员：账号 `server.admin_user`（默认 `admin`），密码取 `server.admin_password`；
留空则随机生成，写入 `data/initial_admin_password.txt`，并在服务日志与部署输出里打印一次。**登录后请立刻改密码。**

## 四、后台七个板块（入口只在隐藏路径下）

后台挂在 `server.admin_path`（默认 `/admin`，**建议改成别人猜不到的路径**），前台不显示任何入口。

| 板块 | 内容 |
| --- | --- |
| **仪表盘** | 用户数/授权码数/任务数、累计与今日 AI 费用、DeepSeek 配置状态、最近任务 |
| **用户管理** | 新建/编辑/改密/禁用/删除用户，生成 API Key |
| **授权码管理** | 批量生成、改次数、重置、禁用、删除、复制；每张授权码的 token 与花费 |
| **任务管理** | 全部任务（含授权码、所属用户）、每个任务的 token 与花费、停止/删除/下载日志 |
| **用量与费用** | 按 **授权码** / 账号 / 用户 / 天 / 模型 聚合的 token 与费用，最近 100 条明细 |
| **审计日志** | 登录（含失败）、建用户、生成授权码、扣次、退次、改设置等操作（含 IP） |
| **系统设置** | DeepSeek Base URL / 模型 / API Key、计费单价、刷课默认参数、鉴权与额度策略 |

系统设置里的改动会**写回 `config.yaml`**（改前自动备份为 `config.yaml.bak`），需要
`systemctl restart chaoxing-web chaoxing-serve` 生效。

## 五、Token 用量与费用是怎么算的

刷课本身不消耗 token，花钱的地方只有一处：**章节检测/作业交给大模型搜题**。
每次调用大模型后，程序会把接口返回的 `usage` 记进数据库（带上**授权码**、用户、账号、任务号），
按下面三档计价：

```
费用 = 缓存命中 tokens × 命中单价
     + 缓存未命中 tokens × 未命中单价
     + 输出 tokens × 输出单价
```

* 计价单位：**美元 / 1M tokens**（与 DeepSeek 官方一致）。
* **高峰 / 非高峰**：高峰单价是非高峰的 2 倍。高峰为 UTC 周一至周五 `01:00-04:00` 与 `06:00-10:00`
  （中国法定节假日除外），换算成北京时间是 **09:00-12:00 与 14:00-18:00**；其余时间（包括晚上）按非高峰。
* **缓存命中**：DeepSeek 返回 `prompt_cache_hit_tokens` / `prompt_cache_miss_tokens`，有就精确使用；
  其它兼容接口没有这两个字段时，输入全部按未命中计（略高估，不会低估）。

默认定价（后台可改，配置里的 `pricing` 段）：

| 模型 | 缓存命中 | 缓存未命中 | 输出 |
| --- | --- | --- | --- |
| deepseek-flash | 0.006 | 0.3 | 1.2 |
| deepseek-v4-pro | 0.044 | 1.32 | 3.96 |

> 价格会变，DeepSeek 也可能调整；后台「系统设置 → 计费单价」里可以直接按官网最新数字改。
> 官方定价页：<https://api-docs.deepseek.com/quick_start/pricing>

**能直接回答的问题**：

* 「这张授权码花了多少钱？」→ 后台「授权码管理」每行都显示；
* 「这个任务花了多少钱？」→ 后台「任务管理」/ 控制台任务列表；
* 「刷一个学习通账号花了多少？」→ 后台「用量与费用 → 按账号」；
* 「今天花了多少？」→ 仪表盘「今日 AI 费用」。

### 与官方账单对账

程序统计的是"请求里返回的 usage"，与 DeepSeek 控制台的用量应在同一量级，允许少量差异：

1. **缓存命中判定**：若接口未返回命中字段，程序把输入全按未命中计（偏高）；
2. **失败重试**：超时后重试成功的那次也会计入（官方同样计费）；
3. **连通性检查**：启动时会发一次极小的测试请求（几十 tokens），也会记账；
4. **模型别名**：`deepseek-chat` / `deepseek-v4-flash` 等旧名会折算到等价价位；
5. **峰谷判断**：服务器时钟不准会把高峰算成非高峰（反之亦然），请确保 `timedatectl` 正常。

```bash
# 程序侧：最近 7 天按授权码的花费
curl -s -H "X-Api-Key: $API_KEY" "http://127.0.0.1:8765/admin/api/usage?days=7" | python3 -m json.tool | head -40
# 官方侧：platform.deepseek.com → 用量/账单，按天对比总额
```

## 六、安全建议

1. 把 `server.admin_path` 改成不公开的路径（例如 `/cx-admin-9f2`），减少被扫描的概率。
2. 管理员用强密码，部署后立刻修改初始密码；`data/initial_admin_password.txt` 用完即删。
3. 控制台与后台只对你的出口 IP 开放（安全组 / 反向代理 + Basic Auth），或用 SSH 隧道：
   `ssh -L 8765:127.0.0.1:8765 root@服务器`。
4. 授权码就是使用凭证，发给谁就等于给了谁刷课次数；建议一人一码、名称里写明归属，便于停用。
5. 定期看「审计日志」，异常登录（大量 `login_failed`）要及时改密码。
6. 数据库 `data/state.db` 里存着账号、授权码与用量，注意备份与权限（仅服务用户可读）。
