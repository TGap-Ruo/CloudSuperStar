# 服务鉴权、后台管理与费用统计

这份文档说明「谁能用、用多少、花了多少钱」三件事。

---

## 一、角色与登录

| 角色 | 能做什么 |
| --- | --- |
| **管理员**（admin） | 进入管理后台：管用户、发卡密、看全部任务、看用量与费用、改系统设置；也能使用刷课控制台 |
| **普通用户**（user） | 只能使用刷课控制台，受「剩余次数 + 每日任务上限 + 并发上限」限制，看不到别人的任务 |

* 账号由管理员在后台创建，**没有自助注册**。
* 首次部署会自动创建初始管理员：账号取 `server.admin_user`（默认 `admin`），密码取
  `server.admin_password`；如果留空则随机生成，写入 `data/initial_admin_password.txt`，
  并在服务日志与部署输出里打印一次。**登录后请立刻改密码**。
* 登录失败限流：同一 IP 5 分钟内失败 8 次后拒绝登录。
* 会话用签名 Cookie，默认有效期 `server.session_timeout_minutes`（12 小时）；密钥持久化在
  `data/.session_secret`（权限 600），服务重启不会导致掉线。
* 后台入口路径由 `server.admin_path` 决定（默认 `/admin`，**建议改成别人猜不到的路径**）。

程序化调用（脚本/机器人）有两种免登录方式：

```bash
# 方式一：沿用部署时生成的访问令牌
curl -H "X-Token: $WEB_TOKEN" http://127.0.0.1:8765/api/tasks

# 方式二：给用户生成 API Key（后台 → 用户 → API Key）
curl -H "X-Api-Key: cx_xxxx" http://127.0.0.1:8765/api/tasks
```

## 二、卡密（给用户发额度）

后台「卡密管理」可以批量生成三种卡密：

| 类型 | 含义 |
| --- | --- |
| 单次授权 | 一张卡只能被兑换 1 次，兑换后固定加 N 次刷课额度 |
| 有限次数 | 一张卡最多被兑换 M 次（可重复给同一人或多人用），每次加 N 次额度 |
| 无限次数 | 兑换次数不限，但每次兑换仍按 N 次额度增加 |

生成时可设置：

* **每张兑换次数（credits）**：用户输入卡密后得到多少次刷课额度；
* **每张可用次数（max_uses）**：这张卡本身能被兑换几次；
* **绑定用户**：只允许指定用户兑换（留空则任何人可兑换）；
* **到期时间**：`2026-12-31` 或 `2026-12-31 23:59:59`，留空表示长期有效。

用户在控制台点「兑换卡密」输入卡密即可充值。卡密可以被禁用、重置（已用次数清零）、删除。

## 三、额度规则

* 每 **启动一个刷课任务** 扣 `server.credits_per_task` 次（默认 1 次）。只有"真正开始刷"才扣：
  单个账号模式里"登录并读取课程列表"这一步不扣。
* **任务最终失败会自动退还**（`server.refund_on_failure: true`）。用户手动停止、成功、部分成功都不退。
* 用户的 `daily_task_limit`（每日任务上限）为 0 表示不限；超限时启动任务会被拒绝。
* 管理员额度是「不限」（credits = -1），不受限制。
* 每一笔扣减/退还都写进 `credit_usages` 表，后台能看到「今日已用」和明细。

## 四、后台七个板块

| 板块 | 内容 |
| --- | --- |
| **仪表盘** | 用户数/卡密数/任务数、累计与今日 AI 费用、DeepSeek 配置状态、最近任务 |
| **用户管理** | 新建用户（角色、额度、每日上限、并发上限、备注）、编辑、改密、生成 API Key、删除 |
| **卡密管理** | 批量生成、搜索、复制、启用/禁用、重置已用次数、删除 |
| **任务管理** | 全部任务（含所属用户）、每个任务的 token 与花费、停止/删除/下载日志 |
| **用量与费用** | 按账号 / 用户 / 天 / 模型聚合的 token 与费用，最近 100 条明细 |
| **审计日志** | 登录、登录失败、建号、发卡、兑换、扣费、退款、改设置等操作记录（含 IP） |
| **系统设置** | DeepSeek Base URL / 模型 / API Key、计费单价、刷课默认参数、鉴权与额度策略 |

系统设置里的改动会**写回 `config.yaml`**（改前自动备份为 `config.yaml.bak`），需要
`systemctl restart chaoxing-web chaoxing-serve` 生效。

## 五、Token 用量与费用是怎么算的

刷课本身不消耗 token，花钱的地方只有一处：**章节检测/作业交给大模型搜题**。
每次调用大模型后，程序都会把接口返回的 `usage` 记进数据库，并按下面三档计价：

```
费用 = 缓存命中 tokens × 命中单价
     + 缓存未命中 tokens × 未命中单价
     + 输出 tokens × 输出单价
```

* 计价单位：**美元 / 1M tokens**（与 DeepSeek 官方一致）。
* **高峰 / 非高峰**：高峰时段单价是非高峰的 2 倍。DeepSeek 的高峰为
  UTC 周一至周五 `01:00-04:00` 与 `06:00-10:00`（中国法定节假日除外），其余时间按非高峰计。
* **缓存命中**：DeepSeek 返回 `prompt_cache_hit_tokens` / `prompt_cache_miss_tokens`，
  有就精确使用；没有（如其它兼容接口）就把输入全部按未命中计（略微高估，不会低估）。

默认定价（后台可改，`pricing` 段）：

| 模型 | 缓存命中 | 缓存未命中 | 输出 |
| --- | --- | --- | --- |
| deepseek-flash | 0.006 | 0.3 | 1.2 |
| deepseek-v4-pro | 0.044 | 1.32 | 3.96 |

> 价格会变，DeepSeek 也可能调整；后台「系统设置 → 计费单价」里可以直接按官网最新数字改。
> 官方定价页：<https://api-docs.deepseek.com/quick_start/pricing>

**每条记录的归属**：写用量时会带上 `user`（谁提交的任务）、`account`（任务内部账号名）、
`task_id`（任务号）。所以你可以：

* 在「任务管理」看到**单个任务花了多少钱**；
* 在「用量与费用」看到**每个学习通账号、每个用户、每天、每个模型**的累计花费；
* 结合卡密额度，算出每个账号的"成本"与"收入"。

### 与官方账单对账

程序统计的是"请求里返回的 usage"，和 DeepSeek 控制台的用量**应该在同一量级**，允许有少量差异：

1. **缓存命中判定**：官方按实际命中计算，若接口未返回命中字段，程序会把输入全按未命中计（偏高）；
2. **失败重试**：超时后重试成功的那次也会计入（官方同样计费）；
3. **连通性检查**：启动时会发一次极小的测试请求（约几十 tokens），也会记账；
4. **模型别名**：`deepseek-chat` / `deepseek-v4-flash` 等旧名会被折算到等价价位；
5. **峰谷判断**：如果服务器时钟不准，可能把高峰算成非高峰（反之亦然）。请确保 `timedatectl` 正常。

对账方法：

```bash
# 程序侧：最近 7 天各账号花费
curl -s -H "X-Api-Key: $API_KEY" "http://127.0.0.1:8765/admin/api/usage?days=7" | python3 -m json.tool | head -40

# 官方侧：登录 platform.deepseek.com → 用量/账单，按天对比总额
```

## 六、安全建议

1. 把 `server.admin_path` 改成不公开的路径（例如 `/cx-admin-9f2`），减少被扫描的概率。
2. 管理员用强密码，部署后立刻登录修改初始密码；`data/initial_admin_password.txt` 用完即删。
3. 控制台只对本机或你的出口 IP 开放（安全组 / 反向代理 + Basic Auth），或者用 SSH 隧道：
   `ssh -L 8765:127.0.0.1:8765 root@服务器`。
4. 给不同用途分别生成 API Key，泄露后单独删除即可。
5. 定期查看「审计日志」，异常登录（大量 `login_failed`）要及时改密码。
6. 数据库 `data/state.db` 里存着账号、卡密与用量，注意备份与权限（仅服务用户可读）。
